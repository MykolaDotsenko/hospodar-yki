# 18 — Інтерактивні вправи та візуальне навчання: наукова база й UI/UX-рішення для Hospodar YKI

**Дата:** 21.10.2026 · **Статус:** evidence-informed product design / заплановані функції, НЕ підтверджена ефективність реалізації Hospodar YKI.  
**Аудиторія:** дорослі, українськомовні, фінська приблизно A2.2 → B1/B1+, YKI keskitaso.  
**Межі огляду:** цільовий огляд вибраних академічних праць і нормативних джерел; не PRISMA systematic review. Відокремлюємо загальну науку навчання від прямих L2-доказів, а перевірені ефекти — від власних UX-гіпотез.

**Інтеграція:** [головне ТЗ](../../docs/15-two-modes-skill-scopes.md) · [MVP ТЗ](../../docs/11-mvp-product-requirements.md) · [методики (67)](../../pedagogy/08-learning-methods-evidence-2026-10.md) · [колір/увага](../../design/17-color-attention-l2-deep-dive.md) · [JSON-контракт](interactive-visual-learning-v1.json).

## 1. Executive decision

**Наша основна одиниця UX — не картка, а навчальний цикл:** `змістовне завдання → власна відповідь без розкриття ключа → короткий специфічний feedback → самостійне виправлення → новий контекст без підказки → відкладена незалежна перевірка`.

Візуалізація повинна **створювати корисні зв'язки або спрямовувати увагу**, а не забирати увагу кольорами/анімаціями. Інтерактивність повинна **вимагати мисленнєвої дії**, а не тільки кліку. Навчальний режим допускає поступову підтримку; екзаменаційний — жодної навчальної підказки під час спроби.

Заборонено називати будь-який прийом «підвищує пам'ять на X%» без власного контрольованого експерименту. У таблиці оцінки /100 — **експертний пріоритет для продукту**, а не розмір наукового ефекту чи ймовірність скласти YKI.

## 4. Канонічні UX-потоки — придатні до реалізації

### 4.1 Фінські місцеві відмінки, без навчання вгадувати колір

1. Зміст: «Куди йдеш?» / `Minne menet huomenna?` → prompt `Menen ___ (kirjasto).` Без позначки `-oon`, без pre-answer animation.
2. Учень **друкує** `kirjastoon`, а не лише вибирає з трьох варіантів.
3. Якщо помилка, cue 1: `mihin?` — *наведення*, не відкрита правильна форма. Після повторної спроби — ключ, коротка причина та одна видима відповідність `mihin → kirjastoon` підкресленням + значущим кольором.
4. Transfer: `Mihin menet töiden jälkeen?` — нова вільна відповідь, жодного cue.
5. Пізніше — нова `unseen` форма й нова ситуація. `correct_with_hint` та `correct_unassisted` зберігаються **окремо**.

### 4.2 Аудіо 2–3 хвилини (B1), справжнє розуміння

1. Показати ціль ситуації та 1 коротке питання-передбачення, не давати транскрипт чи готову відповідь.
2. Слухання нормального темпу; питання на `gist` перед `detail`, потім практичний висновок/рішення.
3. Після незалежного submit — за потреби `replay`, `captions (FI)`, `transcript`; синхронно підсвічувати **одну поточну репліку**, без караоке-декору.
4. Після feedback — новий уривок/голос із подібною функцією **без субтитрів**; перевірити самостійну comprehension. Опори як навчання ≠ право підказувати на симуляції.
5. Для B1 потрібні автентичні сучасні записи, верифіковані timestamps і ліцензія; не маскувати синтетичну начитку під багатоголосий запис.

### 4.3 Зображення як джерело інформації, а не прикраса

- Ситуація: автобусний розклад / лист орендодавця / оголошення роботи / чек. Користувач отримує **доказ із реального носія інформації** й виконує дію: знайти час, уточнити умову, написати відповідь.
- Значущі відповідності сигналізуються тільки **після самостійної відповіді**, або під час окремого guided walkthrough, що не враховується як unassisted performance.
- Потрібна доступна текстова альтернатива для кожного зображення; зображення не повинне бути єдиним способом відповісти.

### 4.4 Вільне говоріння й письмо

- `Prompt → Record/type → Submit → Content feedback → Form feedback → Self-repair → New prompt`.
- Не підміняти семантичну якість наявністю окремих «правильних» слів; експертна або калібрована оцінка потрібна для CEFR/YKI-подібних висновків.
- Відсутній мікрофон/погане ASR/порожній відгук — технічний стан, **не** помилка знань.

## 5. Вимоги до взаємодії / візуальної системи

- **Cognitive economy:** одне головне завдання на екран; мінімум вторинної навігації під час відповіді; не показувати великі анімації, очки й progress popup посеред слухання.
- **Signal ≠ decoration:** не більше одного смислового фокуса на етап; колір + текст/підкреслення/іконка, нейтральний текст завдань; уникати rainbow grammar.
- **Feedback hierarchy:** спочатку «чи досягнуто комунікативної мети», потім 1–2 виправлення, після цього необов'язкове докладне пояснення.
- **Hint ladder:** `none → metacognitive cue → linguistic cue → explicit explanation`. Ключ/правильна форма лише у `feedback/review`. Складність і таймінг підказок — продуктова гіпотеза, потребує тесту.
- **Cue fading:** у повторних та unseen tasks опори зменшуються, не винагороджувати успіх із cue як незалежний.
- **Not only taps:** `MCQ` і `drag-drop` корисні для обмеженої діагностики, але не підміняють `typed/open/voice` генерацію.
- **No AI sameness:** фірмові `Поріг → Маршрут → Дія`, UI бренд-токени без стандартних purple blobs, авторські фінські контексти. Не генерувати фото «для краси».
- **Accessibility:** WCAG 2.2 AA; 4.5:1 звичайний текст, 3:1 великі символи/важливі UI елементи за релевантними критеріями, клавіатура, screen-reader labels, visible focus; no color-only meaning, reduced motion, pause/stop for nonessential motion, touch alternative to drag, текстова альтернатива звуку, high-contrast/calm mode.
- **Exam isolation:** у `exam` ніяких trainer hints, key exposure, післяклікової корекції, content gloss, karaoke captions, surprise mascot. Лише офіційно підтверджені параметри екзамену, решта `practice simulation`.
- **Provenance:** фото/аудіо/транскрипт/схема мають `source_id`, `license`, `teacher_review`, `content_version`; для згенерованого оригінального контенту теж є S2 QA.

## 6. Мінімальний data contract (planned)

Універсальна `LearningInteraction` з полями:
`task_id, content_version, mode, skill, task_pattern_id, target_chunk_ids[], prompt, response_modality, attempt_phase, user_response, hint_level, correctness_type, feedback_evidence, feedback_meaning, feedback_form, transfer_task_id, source/license, teacher_review_status`.

Зберігати локально `first_attempt_result`, `hint_used`, `repair_result`, `transfer_first_attempt`, `retest_at`, `retention_7d`, `retention_14d` та версію завдання. Ключі `exam` не використовувати в навчальному preview; у статичному клієнті цілком приховати ключі технічно неможливо — не стверджувати протилежне.

**Окремо**: `objective_exact/normalized/acceptable_variant`, `teacher_review_required`, `not_assessed`. Для open writing/speaking за замовчуванням `ungraded`, без невалідованого YKI балу.

## 8. План перевірки користі (не плутати product analytics із науковим доказом)

**Пропонований pilot, не виконаний експеримент.** Однакова кількість і якість вправ, приблизно зрівняний час контакту, стратифікація початкового рівня, добровільна згода та локальні aggregate/export analytics. Порівняння **A:** спокійні текстові вправи, retrieval + feedback + SRS; **B:** ті самі механіки плюс строго змістовні інтерактивні візуальні opори / evidence span / згасання cue. Важливо не порівнювати «повне навчання» з «без навчання».

- **Primary:** accuracy першої відповіді на невідоме `unseen uncued` завдання на 7-й день (для лексики/граматики/читання/слухання з перевіреними ключами); не тільки впізнавання знайомої картки.
- **Safety/co-primary для слухання:** gist comprehension без транскриптів; навчання граматики не повинне системно погіршувати розуміння.
- **Secondary:** 14-day transfer, productive attempt rate, time on task, повторні помилки, accessibility errors, screen-reader completion, opt-outs, self-reported cognitive load, drop-off.
- Потрібні попередня реєстрація гіпотез і мінімально важливого ефекту, розрахунок обсягу вибірки, приховане тестове наповнення, blinded teacher scoring для open tasks; якщо малий пілот — формулювати лише usability insights, без причинної заяви.
- Не оптимізувати продукт лише за `streak`, CTR, часом у додатку або числом натискань — вони можуть зростати без реального засвоєння.

## 9. Roadmap / Definition of Ready

**P0:** IV-01…05, IV-12, правила hint/fading/feedback, examsafe policy, доступність, valid source IDs, IV-AC-01…05/08/09/12…15. Частина MVP логіки **вже є**, але ці acceptance gates як комплект ще не пройдені.

**P1:** IV-06…11/13, production voice workflows, authenticated/synced media rights, локальні прогрес-метрики, перевірені Finnish captions і teacher-review.

**P2:** IV-14 та rich visuals лише після результатів usability + delayed independent assessments.

**Редакційне правило:** кожний екран має відповідати на питання «яку саме навчальну дію робить людина тут?» Якщо відповіді немає, це декор, і його не потрібно розробляти.

**Висновок:** `Hospodar YKI` виграє не від кількості кольорових вправ, а від інтерактивного тренування **самостійного розуміння і самостійної мовної дії**, до якої добре спроєктований візуальний шар веде, а потім поступається місцем.
