## 1. Критичний аудит v0.2

**Що зберігаємо:**
- назву **Hospodar YKI**; український слоган **«Фінська для життя. Впевненість для YKI.»**;
- компактний фірмовий **H-поріг** із коротким золотим діагональним кроком, темно-синій/молочний/золотий бренд;
- два режими як дві чіткі шляхи: «Навчання» та «Симуляція»;
- семантичні кольори чотирьох навичок.

**Що покращуємо:**
1. Іконка була єдиним по-справжньому виразним знаком. Колірні смужки чотирьох навичок самі по собі не створюють впізнавану *систему*.
2. Існуючі картки й прогрес легко сприйняти як звичайний освітній dashboard. Змінюємо не кількість прикрас, а **форму корисних елементів**.
3. Вузький екран переповнюють шлюз двох режимів + чотири мітки + навігація. На екрані виконання — пріоритет фінському тексту, мінімум chrome.
4. Ще немає каліброваної контентної ілюстративної мови, правил більш насичених фонів, тесту 16–24 px favicon, dark mode, calm mode.
5. «AI sameness» досі описано переважно як «що не робити». Додаємо **позитивні компоненти, які потрібно впізнавати**.

## 3. Один фірмовий графічний підпис для всього продукту

### 3.1. H-поріг (brand anchor)

`brand/logo/hospodar-yki-mark.svg` — єдиний знак у toolbar, favicon, лендінгу, демо та маркетингових матеріалах. Усі застосування зберігають той самий силует, без альтернативного «AI robot», прапора, екзаменаційної печатки чи випадкової іконки. Юридичну унікальність ще перевірити (PRH, EUIPO, app stores).

### 3.2. Threshold line — функціональна лінія поступу

Нова **фірмова форма**: короткі горизонтальні модулі з діагональним переходом праворуч (`→`/косий зріз), чимось нагадують невеликі етапи переходу через поріг. Замість загальної «зеленої progress bar» застосовувати підписану послідовність:

`Спробував → Помітив помилку → Виправив → Застосував самостійно`.

**Не** вимагати чотири етапи у випадку правильної відповіді (самовиправлення не відбувається): адаптувати labels до фактичного процесу. **Ключ доступності:** поточний етап і завершені етапи доступні текстом для screen reader; сам колір/форма не передають єдину інформацію.

В exam mode використовується та сама форма, але етапи означають **окремі модулі іспиту**, **не** навчальне самовиправлення. Жодних hints у симуляції.

### 3.3. Signature corner

Тільки важливі елементи мають впізнаваний виріз угорі праворуч/золотий короткий штрих (main hero, mode gateway, highlighted mission card). **Не** повторювати силует на кожній картці — стане AI-шаблоном. Для всього іншого — звичайні читабельні прямокутні поверхні.

### 3.4. Typographic fingerprint

Заголовок українською, фінська фраза — в центрі, підпис навички `TEKSTIN YMMÄRTÄMINEN` компактно, великі числові позначки `01/02` тільки для обраних режимів. Основна маса UI без uppercase. Підкреслення значимого слова/частини відмінка, а не декоративний oversize display serif у полі вводу. Fallback `system-ui` має зберігати `ä ö å ї є ґ`.

## 4. Колір із функцією, а не «найяскравіший екран переміг»

### Постійна база

| Роль | Значення |
|---|---|
| Основний бренд | `#083B7A` navy, темно-синій |
| Короткий рух/крок | `#C99135` gold — графічний елемент, не дрібний текст на білому |
| Навчальна поверхня | `#F8F5ED` paper |
| Основний текст | `#18251F` ink |
| Навчання | `#31574C` forest |
| Симуляція | `#083B7A` navy |

### Колірні канали навичок

| Skill | Акцент | Складений із елементів інтерфейсу |
|---|---|---|
| reading | `#126D79` teal | бейдж, активна смуга, номер питання, **не весь текст** |
| listening | `#694E9A` plum | аудіоконтролі / статус прослуховування |
| writing | `#985023` terracotta | шапка завдання, кількість умов, чорновик |
| speaking | `#247244` green | маркер голосової активності, діалогові репліки |

**Активна дія має єдиний кольоровий «якір», а не шість конкурентних акцентів.** На головній сторінці можна показати 4 навички разом, під час вправи лише активну. У режимі іспиту насиченість акцентів менша, навчальні контрастні блоки й позитивні конфеті заборонені. Зберігати основний текст на `paper/white` навіть у colorful mode.

**Колір не доводить запам'ятовування:** він може допомагати візуальній ієрархії й скануванню, але вплив на результати навчання перевіряється експериментом на unseen recall, а не припускається. Підґрунтя: [NN/g: visual hierarchy](https://www.nngroup.com/articles/visual-hierarchy-ux-definition/); [NN/g: extraneous cognitive load](https://www.nngroup.com/articles/minimize-cognitive-load/).

### Mobile 360px first

- Головний gateway може ставати вертикальним, якщо при 200% zoom тексти не вміщуються.
- На активній вправі максимум одна primary CTA, sticky лише за умови що не закриває клавіатуру/поля.
- Службова навігація скорочується; контент і результат важливіші за «красиві декорації».
- Перевірити 320, 360, 390, 768, 1440 px та 200% масштаб без втрати функцій.

## 5.1. Наукове обґрунтування кольору (2026-10-21)

Повний evidence review: [docs/16-color-attention-memory-research-2026-10.md](../docs/16-color-attention-memory-research-2026-10.md). Найсильніша емпірична база — корисність **signaling**, а не магічного `blue for memory`. Тому зберігати чотири брендовані skill colors у навігації, але мовний зміст виділяти **одним контрастним cue + underline лише під час фідбеку після спроби**; transfer, spaced recall та exam без cue.

Палітра сигналу: background `#FFF1C6`, ink `#083B7A`, underline (доступно без визначення кольору). Нейтральні тексти на `paper/white`. Не заливати кожну картку різними кольорами, не створювати неочевидні кольорові mnemonic categories. Аудіотранскрипти підсвічувати тільки після відповіді за перевіреним VTT. Це частина унікальності продукту — **потрібний сигнал у правильну мить**, а не AI visual noise.

## 5.2. Research-backed UI: увага до сенсу, а не лише до кольору

[17 — нова наукова база (2026)](../docs/17-color-attention-l2-deep-dive.md) · [машинозчитувана політика](../research/color-attention-design-policy-v2.json).

З урахуванням Lee & Huang (2008) **підсвічена граматична форма не може підміняти розуміння значення**. У типовому екрані grammar feedback: спершу окремий нейтральний `meaning-first` блок; нижче вузька одна `learning-cue` з правильним словом; у наступному `transfer` обидві cue відсутні. Якщо відомої `meaning_uk` немає, не створювати фіктивного перекладу. Чотири навички мають власні акценти **лише як UI navigation**, не кольорове кодування кожного відмінка.

**Дані про увагу:** 2026 meta включає `color/bold/subtitle` в один visual клас; color eye-tracking Özçelik et al. (2009) показує користь для знаходження відповідностей text ↔ illustration, не для магічного згадування слова. Тому одна інформативна focus cue краще безсистемної різнокольоровості.

**Критерій приймання:** один primary learning target, контраст >=4.5:1, high-contrast/forced-color alternative, neutral background in exam. При валідації performance не менш важливою за grammar accuracy є `gist comprehension`.

## 6. Strict anti-AI-sameness gate

**Reject if:**
1. дизайн використовує «типовий продукт AI» без упізнаваного H-порога (lavender-blue gradients, glass cards, AI bot, floating blobs);
2. на всіх екранах ті самі заголовок + три однакові заокруглені картки;
3. персонажі/ілюстрації на різних екранах мають несумісні стилі;
4. колір з'являється без семантики й конкурує з правильною дією;
5. замість реальних YKI-ситуацій підставлені lorem ipsum або вигадана статистика;
6. бренд зникає, щойно прибрали логотип: немає лінії порога, власної композиції, стабільної семантики.

**Accept if:** фірмовий кут + лінія поступу + один золотий короткий штрих із читаємою типографікою утворюють системний впізнаваний ритм; зміна кольору навички — семантична, не просто ефектна.

## 7. Доступність, не підміна кольором

- WCAG 2.2 AA: **≥4.5:1** для звичайного тексту, **≥3:1** для великого тексту та необхідних нетекстових UI-контролів; перевіряти кожну реальну foreground/background пару. Джерело: [W3C WCAG 2.2](https://www.w3.org/TR/WCAG22/).
- Інтерактивні елементи мають помітний фокус і щонайменше **24×24 CSS px**, якщо не застосовується виняток (для основних CTA бажано ≥44px висоти).
- Контролі мають доступні назви, жоден статус не закодований лише кольором, повага до `prefers-reduced-motion`.
- Calm/low-stimulation mode — цільовий P1: вимкнути зайву анімацію, сховати декоративні кольорові плашки, зберегти розбірливу семантику навичок.
- Не говорити, що нинішній прототип уже сертифікований WCAG AA: автоматичні тести кольорів — лише частина перевірки.

## 8. Acceptance gate + вимірювані гіпотези

| Перевірка | Як виміряти | Критерій релізу |
|---|---|---|
| **Icon recognition** | 16/24/48px серед 6–8 навчальних логотипів | принаймні 80% користувачів після короткого ознайомлення вибирають бренд правильно — **ціль, не факт** |
| **Without logo** | замаскувати назву та SVG, 3 скриншоти | якісне порівняння: впізнають лінію/кут/ієрархію |
| **5-second first impression** | екран на 5 сек → назва продукту/режим | ≥80% правильно вибирають різницю «Навчання vs Симуляція», **ціль** |
| **One primary action** | експертний чек усіх 10 screen states | одна домінантна дія, відсутність decorative interference |
| **Color semantics** | дати користувачу 4 навички в різних контекстах | правильно зіставляє label, icon, color без необхідності лише кольору |
| **Cognitive load** | time-on-task, помилки, drop-off; порівняти colorful vs calm | жодного істотного погіршення виконання на кольоровому варіанті |
| **Access** | axe + клавіатура + screen reader + zoom + мобільні браузери | критичних accessibility blockers немає |
| **Trademark** | PRH/EUIPO/назви застосунків | юридичний аудит завершено перед публічною реєстрацією |
| **Authenticity** | audit exam screens | жодного OPH endorsement чи фейкових YKI grades |

**DoD:** новий компонент ThresholdLine і семантичні кольори реалізовані; усі екрани дотримуються двох режимів, реальних UX-обмежень та anti-sameness; перевірки й користувацьке дослідження заплановані (не записані як проведені).

### Implementation stages

- **P0:** design rules and tokens in repository, CSS for meaningful `step` signature and a focused color hierarchy, automated contract checks, one logo in 2 entry pages.
- **P1:** skill-aware task templates across four modules, component library with Figma-like specimens, calm mode, 200% zoom and screen reader manual QA.
- **P2:** real distinctiveness benchmark vs competitors; copy and illustration commissioning in one editorial style, trademark registration after professional checking.

**Status note:** user-visible branded mode gateway and 4-skill labels exist, but full 4-skill content router / rich mode picker remains unfinished. Do not describe Design System v0.3 as a finished multiplatform visual system.
